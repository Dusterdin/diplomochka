▸ МІНІМАЛЬНИЙ_DEVKIT.SCH v3.0

Мета цієї плати — не телефон, а перший впевнений крок: завантажити bitstream в Agilex 5E, підняти Linux на ARM HPS (Cortex-A55), побачити блимання GPIO. Список нижче — реальні компоненти, перевірені проти трьох офіційних виробничих плат на тому самому BGA-пакеті B32A. v3.0 закриває всі критичні прогалини v2.0: тактування USB-моста, рівень-шифтер для JTAG, EEPROM ідентифікації, достатній запас струму по 3.3V та RTC-кварц.

✓ Bitstream через USB-C/JTAG ✓ Linux на HPS ✓ GPIO тест (LED + кнопки) ✓ Перевірений power-tree ✓ JTAG level-shift 3.3V→1.8V
Список звірений проти трьох реальних виробничих плат на тому самому BGA-пакеті B32A (32×32мм), що і твій A5EA007BB23BE6S: iWave iG-RainboW-G58M SOM Datasheet (PMIC, power tree, clocking), Critical Link MitySOM-A5E Datasheet та MitySOM-A5E Dev Kit Datasheet (USB-C, microSD, EPE-вимоги). Додатково: FTDI FT2232H Datasheet (кварц 12MHz, EEPROM), TI SN74AXC4T774 Datasheet (direction-controlled level shifter для JTAG).
⚠ v3.0 — ВИПРАВЛЕНО ПІСЛЯ ДРУГОЇ ПЕРЕВІРКИ (критичні прогалини v2.0)
1) FT2232HQ не запуститься без власного 12MHz кварцу — додано. 2) Без EEPROM 93LC46B Quartus Programmer бачить плату як "Generic FTDI", а не як USB-Blaster II — додано. 3) TPS62177 (500mA) на 3.3V лінії був на межі — замінено на TPS62130 (3A, pin-to-pin сумісний), бо FT2232H в High-Speed + QSPI flash + логіка LED разом легко з'їдають 300-400mA. 4) RTC у DA9062 не цокатиме без кварцу 32.768kHz — додано. 5) Найкритичніше: FT2232HQ працює на JTAG-стороні від 3.3V, а SDM-банк конфігурації Agilex 5 (VCCIO_SDM) — це 1.8V. Пряме підключення спалить SDM. Додано direction-controlled level shifter SN74AXC4T774 (TI офіційно рекомендує саме його для JTAG: 4-bit, push-pull, до 380Mbps, робочий діапазон 0.65–3.6V) між FT2232HQ і JTAG-піном FPGA.

01Ядро — сам чіп

Без цього все інше не має сенсу. A5EA007BB23BE6S — у тебе вже є в базі, статус "bad" через довгу доставку. Найдовша поставка визначає терміни всього проєкту, тому реєстрація через викладача в Altera University Program — пріоритет №1, паралельно з замовленням решти компонентів.

02Живлення — power tree (виправлено й перевірено двічі)

Agilex 5E має окремі рейки: справжнє core (VCC/VCCP, 0.70-0.90V SmartVID), VCCRCORE periphery (1.2V), VCCIO_SDM/VCCIO_HPS (фіксовані 1.8V), і HVIO/HSIO банки під твою периферію. DA9062 — той самий чіп що в офіційному iWave SOM, бере на себе все periphery/IO живлення через 4×Buck + 4×LDO по I2C (адреса 0x58 в iWave, перевір під свій A5EA007). Для справжнього core з SmartVID потрібен окремий регулятор з апаратною підтримкою PMBus — TPS546D24A чує команди напруги напряму від SDM, на відміну від простого adjustable buck. Окрема 3.3V лінія для USB/JTAG/clock логіки тепер на TPS62130 (3A) замість заниженого 500mA варіанту — FT2232H в High-Speed режимі + активне читання QSPI flash легко з'їдають 300-400mA разом. RTC backup через coin cell тримач і кварц 32.768kHz — для повноцінної роботи VCCBAT/RTC піна PMIC.

03Пам'ять — без неї HPS не запуститься

SDM завжди вантажить FSBL з QSPI flash першим у режимі Active Serial — це обов'язково для автономного завантаження без програматора. Для HPS потрібен окремий LPDDR4 для робочої RAM — не опціонально, без RAM Linux просто не підніметься (офіційний iWave SOM рекомендує 1×32bit LPDDR4 для HPS окремо від FPGA fabric RAM). MicroSD як носій rootfs — найпростіший спосіб для першої версії, не потребує окремого BGA eMMC чіпа.

04Тактування — без цього нічого не стартує

Найлегше забути і найкритичніше. Officially iWave SOM datasheet вимагає окремий HPS тактовий генератор заведений на виділений HPS IO pin — без нього ARM-ядро ніколи не прокинеться. Окремо: FT2232HQ потребує власний 12MHz кварц з двома конденсаторами обв'язки 18-22pF — без нього USB-міст не підніме навіть High-Speed enumeration, і JTAG/UART просто не з'явиться в системі. Офіційний SOM також використовує 199.95MHz диференційний clock для LPDDR4 банків від окремого clock synthesizer — для мінімального devkit без важкої FPGA-логіки можна обійтись простим HPS-генератором на старті і додати LPDDR4 clock synthesizer окремим кроком коли підключатимеш RAM.

05Програмування та конфігурація (з level-shifter)

MSEL[2:0] вибирає режим завантаження (JTAG / Active Serial Fast / Standard) і зчитується SDM лише раз — при power-on, тому потрібен фізичний DIP-перемикач для зручного тестування без перепайки. nCONFIG, nSTATUS, CONF_DONE — дедіковані піни SDM з резисторними підтяжками. FT2232HQ вже є в базі — той самий принцип що в Critical Link MitySOM-A5E Dev Kit (один чіп = JTAG канал A + UART канал B для HPS консолі через один USB-C кабель), але працює на стороні USB при 3.3V, тоді як SDM-банк FPGA — 1.8V. Критично: без рівень-шифтера SN74AXC4T774 між ними — пряме підключення може пошкодити SDM. EEPROM 93LC46B прошиває VID/PID/дескриптори, щоб Quartus Programmer розпізнав плату саме як USB-Blaster II, а не "Generic FTDI device".

06Індикація та GPIO-тест

І в iWave SOM, і в MitySOM-A5E явно прописані LED для статусу конфігурації — твій єдиний спосіб візуально зрозуміти "бітстрім залився / FPGA в user mode" без осцилографа. Додаткові 2 LED + 2 кнопки на GPIO банку — твій "Hello World": найпростіший проєкт на Verilog (кнопка → LED), наочний доказ для викладача що FPGA fabric реально працює.

07USB-C та допоміжні пасивні елементи

FUSB302 вже в базі — для USB-C достатньо CC-пінів і базового PD на старті. Реальний Critical Link MitySOM-A5E Dev Kit використовує USB-C з обмеженням струму до 1.5A при +5V — цього достатньо для мінімальної плати без важкої периферії. Bulk-набір розв'язуючих конденсаторів та точних резисторів зворотного зв'язку (для TPS546D24A/DA9062, 1% або краще, низький ТКО) — без них схема "на папері" робоча, але на практиці ловить шум, дрейфує по напрузі core і не стартує стабільно.

▸ ПОСЛІДОВНІСТЬ ПЕРШОГО ЗАПУСКУ
01
Живлення: USB-C подає 5V → FUSB302 узгоджує CC → TPS546D24A піднімає core по SmartVID, DA9062 піднімає periphery/IO банки в правильній послідовності, TPS62130 тримає стабільні 3.3V для USB/JTAG логіки.
02
SDM прокидається: читає MSEL[2:0] з DIP-перемикача → визначає режим (спочатку постав JTAG-only, всі High).
03
Перший bitstream через JTAG: Quartus Programmer (бачить плату як USB-Blaster II завдяки прошитій EEPROM) → FT2232HQ Channel A (тактується власним 12MHz кварцом) → SN74AXC4T774 переводить 3.3V→1.8V → TCK/TMS/TDI/TDO на SDM → CONFIG_DONE LED загорається.
04
Hello World на fabric: найпростіший Verilog (кнопка→LED) для демонстрації, що логіка реально працює.
05
HPS oscillator + LPDDR4: підключаєш RAM, заводиш тактовий генератор → ARM Cortex-A55 готовий завантажувати U-Boot.
06
Linux на HPS: microSD з образом Yocto/Linux → FT2232H Channel B (UART) → бачиш консоль завантаження на ноутбуці.
07
Перейти на QSPI: переключаєш MSEL на Active Serial → записуєш бітстрім в MT25QU128 → плата вантажиться автономно без JTAG-кабелю.
▸ ЧЕК-ЛИСТ ПЕРЕД ЗАМОВЛЕННЯМ
Перевір Early Power Estimator (EPE) для Agilex 5E у Quartus — і Critical Link, і iWave прямо радять цей інструмент для розрахунку реального струму під твою конфігурацію A5EA007, перш ніж фіналізувати номінали TPS546D24A.
Звір власний BGA pinout A5EA007BB23BE6S з офіційними Pin Connection Guidelines (Agilex 5) — назви рейок (VCC, VCCP, VCCRCORE, VCCIO_HPS, VCCIO_SDM) повинні точно збігатись з конкретним device group твого пакету.
MSEL спочатку постав у режим JTAG Only (всі High) — найпростіший спосіб залити перший тестовий бітстрім без QSPI flash взагалі; QSPI підключаєш другим кроком для Active Serial режиму.
DA9062 I2C адреса в офіційних SOM варіюється (0x58 в одній ревізії iWave datasheet, 0x48 в іншій) — перевір актуальну версію для своєї ревізії чіпа перед розводкою I2C0.
Перед замовленням BGA-чіпів (LPDDR4, QSPI flash) перевір мінімальну партію і ball pitch — потрібен мінімум 6-шаровий стек PCB з контролем імпедансу для DDR-трас.
HVIO_ENABLE сигнал (як в Critical Link datasheet) — поки локальні живлення FPGA не стабілізувались, не подавай сигнали на user IO; використай цей пін для секвенування власної периферії.
JTAG level-shift: SN74AXC4T774 — направлений (direction-controlled) шифтер, тому йому треба DIR-пін, прив'язаний по логіці JTAG (TDI/TMS/TCK йдуть в FPGA, TDO йде назад) — звір з даташитом TI перед розводкою, неправильний напрямок = немає зв'язку.
USB-C диференціальні пари D+/D- від конектора до FT2232HQ: тримай 90Ω диференційний імпеданс, веди парою, без різких 90° поворотів — типова вимога для USB High-Speed, інакше підвисання enumeration.
Резистори зворотного зв'язку TPS546D24A та DA9062: бери 0.1-1% точність з низьким ТКО — похибка в пару відсотків на core rail (0.7-0.9V) означає реальний перегрів FPGA.
